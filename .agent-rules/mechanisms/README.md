# 机制文档目录（mechanisms/）

本目录存放项目稳定机制文档，描述系统当前已经存在的链路、协议、数据契约、风险边界。

## 判据

写"系统现在如何工作、接口如何协作、字段如何解释"，放本目录。
若是"必须/不要"的执行约束，放 `../rules/`；若是"本期要改成什么样"，放 `../dev-plans/`。

## 约定

- 一个机制主题一个文件，文件名用语义化短横线命名。
- 机制文档描述"系统是什么样"，是开发计划的事实依据；开发计划顶部应反向链接到对应机制文档。
- 机制约束、协议契约、风险条款集中写在机制文档里，开发计划只引用不复制。
- 新增 / 删除机制文档后，同步更新本清单与 `../README.md` §6（双索引防漂移）。
- 每当 Agent 完成分析、梳理、排障复盘、架构理解或项目链路确认任务后，若产出了后续开发或维护可复用的稳定事实，必须新增或更新相应机制文档。
- 机制文档保持简洁，聚焦机制运行链路；禁止写的内容见下方「禁止写的内容」清单。

## 机制文档结构（七段强制）

每份机制文档**必须**包含以下七个段落，缺一不可：

1. **结论**：一句话说明这条机制解决什么事。
2. **涉及对象**：表格式列出相关文件、接口、表，每项注明角色。
3. **运行链路**：ASCII 图按步骤描述从入口到结果的完整流转。
4. **使用点**：列出当前有哪些地方调用了这条机制。
5. **修改点**：表格式给出「要做什么 → 改哪里 → 怎么改」。
6. **关键约束**：不超过 6 条，只写后续开发必须注意的不变量。
7. **维护方式**：新增、排查、验证的具体操作方法。

末尾写 `> 更新时间：YYYY-MM-DD`。

### 禁止写的内容

- 大段代码示例（最多保留 1-2 行关键调用签名）
- 方案论证与决策树（属 dev-plans/）
- 长篇背景说明（属 docs/）
- 超过 150 行
