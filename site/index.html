Pulse Agent 订阅 BlueOS 系统自带的健康与传感器接口，不自研监测。本地规则先筛掉噪声，跨过闸门的事件才交给 LLM，结果以振动或通知落回手腕。

01 / 形态

被事件唤醒，不是被问话唤醒

手表最强的是被动感知和腕上振动，最弱的是输入。所以 Pulse Agent 没有聊天框，由传感器事件和外部调用触发。

  1. 1

    感知

    调用系统接口订阅心率、佩戴状态、抬腕和计步。数据由 BlueOS 的健康与传感器服务提供。

  2. 2

    闸门

    声明式的单信号规则：数据类型、比较符、阈值、持续时长、静默期。不为每个样本烧电。

  3. 3

    思考

    只有跨过闸门的事件进入 LLM，由它结合事件内容和本地工具给出结论。

  4. 4

    输出

    落回腕上，一次振动或一条通知。不需要你在手表上操作。

02 / 闸门

规则给 LLM 把门

下面的条件直接取自仓库里的 gate-conditions.json。拖动数值和持续时间，看看什么样的样本值得叫醒 LLM。

  • 感知
  • 闸门
  • LLM
  • 振动

闸门只做单信号比较，不支持 AND / OR。多信号的融合交给 LLM，不往闸门条件里堆。

默认条件集只放已有采样来源的条件。目前接上的是心率与佩戴状态；血氧和电量还没有对应的系统接口接入，没写进来。

03 / 能力

已实现与规划中，分开写

能力清单取自 watch-capabilities.json，外部生态按它发现并接入。规划中的能力，接入方不应依赖。

04 / 快速开始

配好模型，构建，部署

手表上不输入配置。模型供应商、地址和 Key 在本机 CLI 或本地 Web 控制面完成；手表未配置时会显示设备码二维码，供手机扫码填写（一期代码已接入，真机待验）。

shell 
# 起设备码 H5，手机扫码填 Key
node scripts/setup-server/server.js --host 0.0.0.0

# 或用 CLI 配置，再同步到模拟器
node scripts/llm-config.js set --provider deepseek \
  --endpoint https://api.deepseek.com/v1/chat/completions \
  --model deepseek-chat --api-key-stdin < api-key.txt
node scripts/llm-config.js sync-simulator

# 构建并部署
./scripts/build-blueos.sh
./scripts/deploy.sh

setup-server 带 --host 0.0.0.0 会监听局域网，且用于填写 API Key。只在可信网络里使用，用完关闭。
